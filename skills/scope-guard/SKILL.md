# Scope guard

Делай ровно то, что просили. Всё соседнее — предложи, не делай.

## Pre-flight (30 секунд, перед первой правкой)
1. **Просили:** одна фраза.
2. **Вопрос или команда?** Вопрос, сравнение, «можно ли?», «как думаешь?» — это только ответ. Действия на стенде — после явного «делай/ставь/обновляй».
3. **Затрону:** список файлов/сервисов/пакетов. Если >3 файлов или есть сервис — коротко назови пользователю.
4. **Не затрону:** соседний код, рефакторинг «заодно», форматирование чужих файлов, чужие правки в dirty worktree.

## Классы риска → что делать
| Класс | Примеры | Действие |
|---|---|---|
| Необратимое | `rm -rf`, `git reset --hard`, drop БД, перезапись конфигов без бэкапа | план + явное подтверждение + бэкап |
| Диски | fstab, mount, разметка, loop, resize | ТОЛЬКО по скиллу `fstab-disk-safety` |
| Сеть/доступ | iptables, ufw, nginx, порты, VPN, ssh | план + подтверждение + второй канал доступа |
| Сервисы | `systemctl restart/enable`, docker, cron | подтверждение; перезапуск только через `systemctl`, не `kill` |
| Установка | apt/npm/pip/docker pull | сначала `df -h /`; мало места → сначала очистка стенда; после теста — удалить |
| Секреты | токены, ключи, .env | не печатать, не коммитить, не отправлять наружу |

## Правила
- Бэкап правимого файла: `cp f f.bak-$(date +%F)`.
- Всё, что поставлено/запущено для теста, удаляется после теста (процессы, юниты, кроны, файлы). Проверить `systemctl --failed` и `ps`.
- Нашёл «ещё одну проблему» по ходу — запиши в отчёт как предложение, не чини молча.
- Сомневаешься, входит ли действие в запрос — считай, что не входит, и спроси.

## Классификатор рисков (GREEN/YELLOW/RED)

**GREEN — чтение или локальные обратимые правки в рабочем каталоге: делай сразу.**
- `df -h /`, `systemctl status dsh.service`, `docker ps`, `git status/diff`, `journalctl -u dsh.service -n 50`
- правка файлов проекта внутри своего write scope; `git add`/`git commit` в рабочей ветке
- удаление своих временных файлов из `tools/staging/` после теста

**YELLOW — обратимо, но меняет состояние стенда: план в 1–3 строки + бэкап + сообщить после.**
- правка конфига: `cp /etc/nginx/conf.d/dsh-vpn.conf /etc/nginx/conf.d/dsh-vpn.conf.bak-$(date +%F)` → edit → `nginx -t`
- установка пакетов (сначала `df -h /`); `pnpm install` в проекте; миграция БД после дампа
- `systemctl restart dsh.service` (только через systemctl, не kill); `git push` в свою ветку; чистка тестовых артефактов после теста

**RED — необратимое или радиус поражения вне задачи: ОБЯЗАТЕЛЬНО план + бэкап/откат + явное «делай» пользователя (вопрос ≠ разрешение); нет второго канала доступа — не делать.**
- `rm -rf` вне временного каталога; `git push --force`; `DROP`/`TRUNCATE` в БД; удаление ключей/секретов
- fstab/маунты/разметка/loop/resize — ТОЛЬКО по скиллу `fstab-disk-safety`
- iptables/ufw/сеть/порты; `docker system prune`, `docker volume rm`, удаление контейнеров
- деплой в прод; запись в чужие системы/сервисы
