# Jev Skill Picker

Выбор подходящего скилла из каталога через Jev: skill_search/список скиллов подаётся как варианты в mcp__jev__choice, Jev за ~200мс указывает топ-кандидата и уверенность. Использовать при неоднозначном запросе, многих кандидатах из skill_search, или при делегировании подзадачи субагенту. Механика «скиллы = меню, Jev выбирает» из кейса 5 видео про System One.

## Паттерн
1. Получи кандидатов: `skill_search` (top-k) или список имён из каталога скиллов с краткими описаниями. Кандидатов ≤ 10; если больше — сначала отсей по `noul` «релевантен ли скилл X запросу?» батчем через `mcp__jev__run`.
2. Один `mcp__jev__run`, state = JSON `{request, skills:[{name, one_line}]}`:
   - `pick` choice: ключи = имена скиллов + `none`. Instructions: «какой скилл полнее всего отвечает запросу? none — если ни один».
3. Решение: уверенный топ-1 (доминирует в распределении) → загрузи скилл через `skill`. Распределение размазано (топ-1 < 50%) → реши сам или спроси пользователя.
4. `none` с высокой уверенностью → скилла нет, работай без скилла (не выдумывай имя).

## Правила
- Имена в criteria должны ТОЧНО совпадать с именами скиллов (kebab-case) — по ним идёт загрузка.
- В state — имена и однострочники описаний, не полные тексты скиллов (окно Jev 32k и токены платные за вход).
- Fallback: `skill_search` + своё решение как раньше; ничего не блокируется из-за Jev.
- Калибровка: первые применения проговаривай «Jev выбрал X (p=…); я согласен/нет» — при систематических промахах правь формулировку one_line описаний скиллов, а не игнорируй.
