# Verify before done

Нельзя писать «готово» без проверки результата. Закрытая задача ≠ выполненная команда.

## Шаги
1. **Сверь с запросом.** Перечитай исходную просьбу пользователя. Что именно должно измениться? Критерий успеха — одна фраза.
2. **Проверь фактом, а не предположением.** Выбери самый дешёвый реальный чек:
   - код: тест / build / lint / `node --check` / `python -m py_compile`;
   - сервис: `systemctl status`, `journalctl -u <unit> -n 30`, `curl -sI <url>`;
   - конфиг: перечитай файл после записи, прогони валидатор (`nginx -t`, `findmnt --verify`, yaml-парсер);
   - данные/файлы: `ls -la`, `diff`, `wc`, выборочное чтение.
3. **Проверь побочное.** `git diff --stat` / список затронутых файлов: нет ли лишнего, чего не просили (см. scope-guard). `systemctl --failed` пуст? Не остались процессы и временные файлы от теста?
4. **Негативная проверка** для рискованных правок: убедись, что соседняя функциональность жива (один смежный сценарий).
5. **Отчёт.** В финале: что сделано · чем проверено · что НЕ удалось проверить и почему. Если проверка не прошла — не маскируй, чини или сообщи.

## Антипаттерны
- «Должно работать» без запуска.
- Проверка только happy-path там, где правка касалась ошибок/границ.
- Считать успехом `exit 0`, не прочитав вывод.
- Оставить за собой тестовые юниты, процессы, файлы (директива чистоты стенда).
