# Jev Browser Actor

Выбор следующего действия или целевого элемента в браузере через Jev (mcp__jev__choice/run) по accessibility-tree: быстрый выбор кандидата, проверка безопасности действия, верификация результата. Использовать при браузерной автоматизации (agent-browser, browser-use), когда из дерева доступности видно несколько кандидатов и нужно быстро выбрать правильный.

## Паттерн выбора элемента
1. Собери кандидатов из accessibility-tree (agent-browser `tree`): для каждого — role, name, короткий идентификатор (index/selector). НЕ тащи всё дерево в контекст.
2. Один `mcp__jev__run`, state = JSON `{goal, url, candidates:[{id, role, name}]}`:
   - `pick` choice: ключи = id кандидатов + `none`. В instructions: «какой элемент соответствует цели: <цель>? none — если ни один не подходит».
   - `safe` noul: «безопасно ли кликнуть по выбранному элементу (не удалить, не отправить платёж, не согласиться с условиями)?»
3. Интерпретация: `pick=none` → обнови кандидатов или вернись к LLM. `safe < 0.9` → подтверждение у пользователя.

## Паттерн «что делать дальше»
Застрял (не знаешь следующий шаг): state = цель, URL, последние 3 действия и их результаты, видимые варианты. `next` choice с вариантами действий, которые ты реально можешь исполнить (`click / fill / scroll / back / read_page / give_up`). `give_up` с высокой уверенностью — не долбиться, эскалация к LLM/пользователю.

## Паттерн верификации результата
После действия: `noul` «соответствует ли новое состояние страницы ожидаемому результату?» (state = ожидание + фактический заголовок/текст/URL). < 0.6 → перепроверь скриншотом/чтением страницы.

## Правила
- В state не отправлять куки, токены, содержимое форм с личными данными.
- Нельзя выбирать из того, чего нет в списке кандидатов — список должен быть полным на момент вопроса.
- Fallback: Jev недоступен → выбираешь сам по accessibility-tree, как раньше.
- Ответ Jev — подсказка, не гарантия: перед кликом по деньгам/удалению всегда человек.
