# Fstab / Disk Safety

## Суть
Одна ошибка в `/etc/fstab` (или в разметке/маунтах) = незагружаемый сервер. На удалённой VPS без IPMI/KVM это катастрофа — чинить только через дорогой VNC/резкью-режим. Этот скилл — обязательная дисциплина перед ЛЮБЫМ изменением маунтов, fstab, разметки, loop-образов.

## Железные правила

1. **Никогда не редактировать fstab «вслепую».** После КАЖДОГО изменения — валидация до перезагрузки:
   - `findmnt --verify --verbose` — проверяет fstab целиком (точки маунта, опции, существование устройств);
   - `mount -a --fake` (dry-run) или `mount -o remount /точка` для уже смонтированных;
   - для systemd-маунтов: `systemd-analyze verify`.
   Если валидация недоступна — изменения не применять.

2. **tmpfs опции — только целые числа.** Ядро НЕ принимает десятичные дроби: `size=1.5G` даёт `Bad value for 'size'` и emergency mode при загрузке. Писать `size=1500M` или `size=2G`. Это касается всех ёмкостных опций tmpfs (size, nr_blocks, nr_inodes).

3. **Бэкап перед правкой:** `cp /etc/fstab /etc/fstab.bak-$(date +%F)`. Хранить рабочий fstab в заметках — чтобы при emergency-режиме восстановить одной строкой.

4. **Проверять маунт сразу, не дожидаясь ребута:** `mount -a` — если команда вернулась без ошибок и `findmnt /точка` показывает ожидаемое, ребут безопасен. `mount -a` с битым fstab упадёт с той же ошибкой, что и загрузка.

5. **Не держать в fstab то, что не нужно при загрузке.** Хрупкие/экспериментальные маунты (loop-образы, сетевые ФС) — с опцией `nofail` в 4-м поле: сломаются — система всё равно загрузится. `nofail` обязателен для всего, кроме `/` и критичных путей.

6. **Loop-маунты (образ-файл как ФС):** порядок — создать образ → `mkfs` на образ → `mount -o loop` → перенести данные → проверить сервис работает → только потом прописывать в fstab. В fstab писать путь к файлу-образу и `loop` в опциях. Проверка после ребута обязательна (отдельная точка отказа).

7. **Изменение размеров:** расширять можно онлайн (LV/loop: `truncate`/`lvextend` → `resize2fs` на смонтированной ext4), сжимать — НИКОГДА онлайн (только umount → fsck → resize → mount). Сужение разделов — самая опасная операция: сначала бэкап.

8. **Разметка (fdisk/parted/gdisk):** менять таблицу разделов только на диске, идентифицированном ДВАЖДЫ (`lsblk` + `blkid` + размер). Перепутать vda/vdb = уничтожить чужие данные. После разметки — `partprobe` или ребут.

9. **Правило «открытой консоли»:** любые операции с fstab/разделами выполнять только при живой консоли (SSH с tmux + открытый VNC-путь, если есть). Не делать дисковые операции в последнем доступном канале доступа.

## Восстановление после bad fstab (emergency mode)
1. VNC/консоль хостера → root → система предложит `Ctrl-D` или root-пароль.
2. `mount -o remount,rw /` → исправить fstab → `exec systemctl default` или ребут.
3. Если root-ФС совсем не монтируется: в GRUB (клавиша e в меню → `init=/bin/bash`) → remount rw → чинить.
4. Профилактика: держать в заметках точную строку рабочего fstab и путь к бэкапу.

## Чек-лист перед ребутом после дисковых изменений
- [ ] `findmnt --verify` без ошибок
- [ ] `mount -a` без ошибок
- [ ] все новые маунты с `nofail` (кроме /)
- [ ] бэкап fstab сделан
- [ ] опции tmpfs — целые числа
- [ ] есть второй канал доступа (VNC/резкью) на случай провала
