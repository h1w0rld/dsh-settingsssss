# Description Optimizer (Jev-first, minimal-touch)

Philosophy (пересмотрено 2026-10-04 после фидбека «суть оптимизатора — сократить, а не увеличить»): описание скилла — это триггер. **Минимальный достаточный триггер лучше полного красивого.** Не приводить все описания к «идеальному окну»: сначала скорим оригинал как есть, и короткое описание, прошедшее скор, не трогаем — каким бы маленьким ни было. При доработке провалившихся целиться в объём не нужно: раздувать до 250–350 «для надёжности» — излишнее раздувание контекста; ориентир доработки **≤250 символов**.

## Workflow

### Step 1: Snapshot + audit
`cp -r ~/.agents/skills /tmp/skill-snap-$(date +%m%d)` перед любыми правками. Дамп name + description + длина (python: folded `description: >` склеивать; вложенные ключи `metadata:` / `disable-model-invocation:` после описания вычитать из длины вручную).

### Step 2: Score ORIGINALS — главная фаза
На каждый скилл — 2 реалистичных should-trigger запроса (RU/EN микс, разговорные) + контроли «сосед не ограблен» при конфликтах. ВСЕ вопросы одним batch-вызовом jev (`mcp__jev__run` с `{state, questions}` или CLI `jev run`); в `state` — каталог как есть. Вопрос: «Пользователь пишет: „<q>“. Выберет ли модель скилл <name> как лучший ответ — не соседний скилл и не „никакой“?» Ответы в `answers.<id>.noul`. Стоимость ~$0.0002 на 25 вопросов.

**Порог: ≥0.80 — скилл НЕ трогаем (даже при 30 символах). <0.80 — в доработку.**

### Step 3: Rewrite ONLY failures
Для каждого провала, ориентир ≤250 символов:
- что делает — одна клоза;
- Use when + 2–4 реальные пользовательские фразы (RU+EN);
- развод с соседом одной фразой, только если рядом реально похожий скилл;
- ничего больше: без фич-списков, маркетинга, лицензий.
Если оригинал >450 символов и пришлось резать — вырезанное в тело с заголовком `## ... (from original description)`; при меньшем объёме просто ужать.

### Step 4: Re-score failures
Цель ≥0.80. Если не выходит за 1–2 итерации — усиливать ФРАЗЫ (конкретные слова пользователя), не объём.

### Step 5: Report
Таблица: skill | длина оригинала | скор | вердикт (kept / rewritten) | новая длина | новый скор. Путь снапшота для отката.

## Thresholds
- ≥0.80 → keep as-is (длина не имеет значения — решает скор)
- 0.70–0.79 → точечная правка фраз, минимальный прирост длины
- <0.70 → переписать (≤250)
- >450 символов и скор прошёл → оставить, но пометить в отчёте как кандидата на сжатие (решение за пользователем)

## Jev invocation pitfalls
- jev **MCP server runs with HOME=/dsh**, CLI с HOME=/root — ключи в двух хранилищах. Если MCP вернул "API key is not stored" — `echo "<key>" | /root/.local/bin/jev auth set --provider openrouter`. OpenRouter ключ исторически в /root/.config/jev-cli/credentials.json.
- Абстрактный вопрос «достаточно ли описания?» насыщается на ~0.75 — не использовать, только concrete-query eval.

## DSH catalog specifics (2026-10)
- Скиллы с `disable-model-invocation: true` не инжектятся в каталог агента (0 контекста, триггер только по имени от пользователя). Снятие флага = скилл виден и триггерится из речи, но его описание начинает стоить контекст в каждом диалоге — решать пользователю.
- Скилл без SKILL.md молча не попадает в каталог; нестандартный frontmatter (`allowed-tools: Bash(x *)`) тоже может выкинуть скилл из каталога.
- Новые/изменённые описания подхватываются каталогом на лету, без рестарта.

## Tool descriptions (pnpm patch)
Для тулов плагинов DSH (memory/dtodo, task_board_*, de_channel_send): описания лежат в lib/*.js внутри `~/.dsh/profiles/web/node_modules`, править через `pnpm patch` (patches/ переживают переустановку). Та же методология: скор-фёрст, трогать только провал, ≤250. Грабли: `'` экранировать как `\'` в JS-строках, не съесть запятую, проверять `node --check`. Remote MCP (jev, deploychan) — описания клиентом не правятся, только отключение.

## Реальный срез каталога (2026-10-07)
Модель видит в каталоге только первые `maxDescLength` (=100) символов описания (dsh-skill-folder); хост режет до 500. Поэтому: триггер и «Use when» — в первых 100 символах, хвост работает только для skill_search. Проверка: `python3 /opt/projects/<harness>/tools/skill-eval/skill-eval.py --cut 100 [--overrides new.json]` (до применения) и `tools/skill-lint.py`. Подробности: notes/skills-harness-review.md.

## Проверка здоровья всего харнеса одной командой
`/opt/projects/<harness>/tools/harness-check.sh [--no-eval]`: skill-lint, skill-eval (>=85%), check-patches, бюджет каталога <=5k токенов, ссылки в AGENTS.md, состояние dsh.service. `--no-eval` — без сетевого шага (jev).
После любой массовой переписи описаний прогонять `python3 /opt/projects/<harness>/tools/skill-fidelity.py` (сверка описания с телом скилла и оригиналом через Jev): eval маршрутизации не ловит искажения смысла — «проходит кейс» ≠ «описание всё ещё правдиво».
